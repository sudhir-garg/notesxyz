01 · Overview

What is model quantization?

Model quantization is the process of representing some or all of a neural network's weights and/or activations with fewer bits than the original representation. The purpose is to reduce storage and memory requirements and, when the hardware and kernels support it, improve inference efficiency.

For example, a model may originally store its weights as 32-bit floating-point values (FP32). Quantization can represent those values using 16-bit floating point (FP16 or BF16), 8-bit integers (INT8), or 4-bit representations. Fewer bits per parameter mean less memory is required to store the model.

The central idea Replace a high-precision representation with a lower-bit representation while keeping the model's predictions sufficiently close to the original model's predictions.

Quantization is not exclusive to large language models. It is used in computer vision, speech processing, recommendation systems, NLP models, and edge AI applications. It is especially valuable when a model must run on hardware with limited RAM, VRAM, power, or bandwidth.

Weights

Learned parameters such as the values in linear-layer matrices. Weight quantization reduces the memory used by model parameters.

Activations

Intermediate tensor values produced during the forward pass. Activation quantization can reduce runtime memory and enable integer compute paths.

Inference

The model's prediction or generation phase. Quantization is often used to fit larger models on smaller devices and reduce memory traffic.

02 · Motivation

Why do we need quantization?

Large neural networks contain millions or billions of learned parameters. A parameter is commonly stored as a floating-point number. When every parameter uses 32 bits, the aggregate memory requirement becomes substantial.

Consider a hypothetical model with 7 billion parameters. Storing only its weights in FP32 requires approximately 28 billion bytes (about 26.1 GiB). Loading such a model also requires room for runtime data, temporary tensors, the key-value cache, and the inference engine.

Practical reasons

  • Lower memory footprint: more models can fit within a given GPU or device memory budget.
  • Lower memory bandwidth demand: moving smaller weight tensors can reduce memory traffic, which is important for many inference workloads.
  • Potentially faster inference: supported low-precision hardware instructions and optimized kernels can improve throughput or latency. This is hardware- and workload-dependent, not guaranteed.
  • Edge deployment: quantized models are easier to deploy on phones, embedded systems, and other devices with limited resources.
  • Lower operating cost: a smaller deployment may need fewer or less expensive accelerators, depending on performance requirements.
Quantization does not automatically make every model faster. Smaller weights can reduce memory traffic, but actual speed depends on accelerator support, quantized kernels, batch size, sequence length, and whether the workload is memory-bound or compute-bound. Benchmark the deployed model on the target hardware.

03 · Data representation

Understanding FP32, FP16, BF16, INT8 and INT4

Before understanding quantization, it is useful to know how many bits common numeric formats use. A bit is a binary digit, either 0 or 1. More bits generally allow a format to represent a larger set of values, but the exact range and precision depend on how those bits are allocated.

Floating-point formats

IEEE 754 binary32 (FP32) uses 32 bits split into a sign bit, exponent field, and fraction field. The exponent allows floating-point numbers to represent very small and very large magnitudes.

The sign indicates positive or negative, the exponent controls scale, and the fraction contributes significand precision. The number 7.23 is not stored by putting “7” into the exponent and “23” into the fraction; the IEEE 754 encoding is based on a normalized binary representation.

FP3232 (4 bytes)Full-precision reference, many training workflowsHigh precision and wide dynamic range; largest storage in this table.
FP1616 (2 bytes)Mixed-precision training and inferenceHalf the storage of FP32, but smaller exponent range.
BF1616 (2 bytes)Training and inference on supported acceleratorsSame exponent width as FP32, fewer fraction bits; useful for dynamic range.
INT88 (1 byte)Integer quantization of weights and/or activationsNeeds a mapping such as scale and zero-point to represent real values.
INT44 (0.5 byte)Low-bit LLM weight quantizationTwo 4-bit values can be packed into one byte; metadata and packing affect actual size.
Terminology correction: FP16 versus INT8 FP32 → FP16 is a lower-precision floating-point conversion. FP32 → INT8 uses a discrete integer representation and usually needs quantization parameters such as scale and zero-point. Both reduce storage, but they are not the same numeric conversion.

04 · Memory calculations

How much memory can quantization save?

A useful first estimate is:

Weight storage (bytes) ≈ number of parameters × bits per parameter ÷ 8

The following table shows the raw weight-storage estimate. It excludes quantization metadata, model files' additional structures, runtime buffers, activations, KV cache, CUDA context, and memory allocator overhead.

FP32428 GB (≈26.1 GiB)280 GB (≈260.8 GiB)1×
FP16 / BF16214 GB (≈13.0 GiB)140 GB (≈130.4 GiB)½×

Do not equate model weight size with required VRAM. A 70B model's theoretical INT4 weights alone are around 32.6 GiB. That already exceeds a nominal 32 GB card when measured in GiB, before adding metadata, the KV cache, temporary buffers, or runtime overhead. Real hardware fit must be tested.

Why is the actual memory requirement larger?

  • KV cache: during autoregressive generation, keys and values for previous tokens are stored. Its size depends on architecture, context length, batch size, and cache precision.
  • Activations and temporary buffers: intermediate computation consumes memory.
  • Quantization metadata: scales, zero-points, group information, and packing structures consume additional storage.
  • Runtime overhead: the framework, kernels, memory allocator, and CUDA context also need resources.
  • Training state: gradients and optimizer states can require much more memory than inference alone.

05 · Mathematical foundations

How does quantization work?

Suppose the original model contains floating-point values. We want to map each real-valued value to a smaller set of representable integer levels. An 8-bit unsigned integer has 256 possible values: 0 through 255. A signed 8-bit integer commonly represents −128 through 127, although symmetric quantization often uses −127 through 127 to keep the range balanced around zero.

The mapping must answer two questions:

  1. How much real-valued change corresponds to one integer step? This is the scale.
  2. Which integer represents the real number zero? This is the zero-point.

The affine quantization equations

The commonly used affine mapping is:

q = clip(round(x / s) + z, qmin, qmax)

Where:

  • x is the original floating-point value.
  • q is its quantized integer value.
  • s is the positive scale factor.
  • z is the integer zero-point.
  • q_min and q_max are the allowed integer endpoints.
  • round maps to a nearby integer and clip keeps the result inside the integer range.

To approximately reconstruct the original floating-point value, use dequantization:

x̂ = s × (q − z)

The reconstructed value x̂ is generally close to, but not exactly equal to, the original value x. The difference is quantization error.

Scale and zero-point from a real range

For an asymmetric affine mapping from a real interval [xmin, xmax] to an integer interval [qmin, qmax]:

s = (xmax − xmin) / (qmax − qmin)
z = round(qmin − xmin / s)

The zero-point is then clamped to the representable integer range. Implementations can differ in rounding convention and in how they handle degenerate ranges, so numerical results may differ by one integer step.

06 · Worked calculations

Two step-by-step quantization examples

Example A: map 0 to 1000 into unsigned INT8 (0 to 255)

Suppose all values are non-negative and the observed floating-point range is 0 to 1000. We want to map it to unsigned 8-bit integers, whose range is 0 to 255.

xmin = 0,   xmax = 1000
qmin = 0,   qmax = 255

First calculate the scale:

s = (1000 − 0) / (255 − 0) = 1000 / 255 ≈ 3.9216

Because real zero maps to integer zero in this example, the zero-point is z = 0. Now quantize a value of 250:

q = round(250 / 3.9216) = round(63.75) = 64

So the real value 250 is represented by the integer 64. Dequantizing it gives:

x̂ = 3.9216 × (64 − 0) ≈ 250.98

The reconstructed value is approximately 250.98 rather than exactly 250. That small difference is quantization error.

Example B: map −20 to 1000 into unsigned INT8 (0 to 255)

Now the real range includes negative numbers. We still want to use unsigned integers from 0 to 255, so a non-zero zero-point is required.

xmin = −20,   xmax = 1000
qmin = 0,   qmax = 255

Calculate the scale:

s = (1000 − (−20)) / 255 = 1020 / 255 = 4

Calculate the zero-point:

z = round(0 − (−20 / 4)) = round(5) = 5

Quantize the minimum value −20:

q = round(−20 / 4) + 5 = −5 + 5 = 0

Quantize 250:

q = round(250 / 4 + 5) = round(67.5)

With NumPy's round-half-to-even behavior, 67.5 rounds to 68. A framework may specify a different tie-breaking rule, so verify the exact rounding behavior when reproducing calculations across libraries.

Quantize the maximum value 1000:

q = round(1000 / 4) + 5 = 250 + 5 = 255
What the zero-point accomplishes It shifts the integer representation so that real zero is represented exactly. In this example, real 0 maps to integer 5, while −20 maps to 0 and 1000 maps to 255.

07 · Quantization schemes

Symmetric vs. asymmetric quantization

The difference is how the real-valued range is selected and whether zero is placed at the center of the integer range.

Symmetric quantization

The real range is centered around zero, commonly as [−α, +α]. The integer range is also centered around zero, commonly [−127, +127] for an 8-bit signed symmetric scheme.

s = α / 127,   z = 0

Simple zero-point handling; often used for weights whose distribution is roughly centered around zero.

Asymmetric (affine) quantization

The observed minimum and maximum are mapped to the full integer range. The range does not need to be centered around zero, so the zero-point may be non-zero.

s = (xmax − xmin) / (qmax − qmin)

Can use the available integer levels more efficiently for skewed or non-negative values, such as many activation tensors.

PropertySymmetricAsymmetric / affine
Real rangeCentered around zeroCan be any observed interval
Zero-pointUsually 0 for signed symmetric quantizationMay be non-zero
Typical useWeights with approximately zero-centered distributionsSkewed or non-negative activations
AdvantageSimpler arithmetic in many implementationsUses integer levels efficiently for offset distributions
Potential drawbackMay waste resolution if the data is strongly skewedZero-point arithmetic can add implementation complexity
Important correction about Batch Normalization Batch Normalization is not a quantization technique and is not the definition of symmetric quantization. It normalizes activations during network computation. Symmetric quantization is defined by a quantization range centered around zero and, in the common signed case, a zero-point of zero. Batch Normalization can affect activation or weight distributions, but the two concepts are separate.

Signed versus unsigned 8-bit values

uint8 represents integers from 0 to 255. int8 represents integers from −128 to 127. A non-negative real range can be mapped to uint8. A real range that includes positive and negative values can use signed integers or an unsigned range with a suitable zero-point. Do not confuse “symmetric” with “unsigned”: symmetric quantization is commonly signed and centered around zero.

08 · Calibration

What is calibration in model quantization?

Calibration is the process of estimating the real-value ranges and quantization parameters—such as scale and zero-point—that will be used to quantize tensors. It is particularly important for activations, because their values depend on the inputs passed through the network.

For weights, the tensor values are already available in the trained model, so weight ranges can be measured directly. For activations, a representative calibration dataset is usually passed through the model. Observers collect statistics such as minimums, maximums, or histograms; those statistics are then used to choose ranges.

Common calibration strategies

MethodHow it worksWhen it is useful
Min–maxUses the smallest and largest observed values.Simple baseline; can be sensitive to outliers.
Moving-average min–maxTracks smoothed minimum and maximum values across batches.Can provide more stable estimates when activation ranges vary.
Percentile clippingChooses a range that retains a selected percentage of observed values.Useful when a small number of extreme values would otherwise dominate the range.
Histogram / entropyUses a value histogram and selects a range based on a distribution or divergence criterion.Can balance clipping error and quantization resolution.
MSE-based range selectionChooses a range intended to minimize reconstruction mean-squared error.Useful when minimizing numerical reconstruction error is the target.

Why does the calibration dataset matter?

Imagine a language model deployed for customer support, but calibration is performed only on short, generic sentences. If production prompts contain long conversations, code blocks, or multilingual text, activation distributions may differ. Poorly estimated ranges can cause clipping or excessive rounding error.

  • Use representative inputs from the intended workload.
  • Include realistic prompt lengths and input patterns.
  • Include important edge cases, not only average examples.
  • Validate the quantized model on a separate evaluation set.
Keep the terms separateCalibration selects or estimates the ranges and qparams. Quantization maps the values into the lower-bit representation. They are connected steps, but they are not synonyms.

09 · Practical design choices

Per-tensor, per-channel and group-wise quantization

Scale and zero-point do not always need to be shared by an entire model tensor. The granularity determines how many independent quantization parameter sets are used.

Per-tensor

One scale and zero-point are used for an entire tensor. It is simple and has low metadata overhead, but may not fit every channel's distribution equally well.

Per-channel

Each output channel (or another selected channel axis) gets its own scale, often improving weight quantization accuracy.

Group-wise

A weight matrix is divided into smaller groups, each with its own scale and sometimes zero-point. Group size trades metadata overhead against local precision.

LLM quantization commonly uses weight-only and group-wise schemes because different output channels or weight groups can have different value distributions. Smaller groups can improve accuracy but require more metadata and may change kernel efficiency.

Weight-only versus weight-and-activation quantization

10 · Quantization workflow

Post-Training Quantization (PTQ)

Post-Training Quantization is applied after a model has completed its original training. The trained model's weights are available, and the quantization workflow converts them—and, depending on the method, possibly its activations—to lower precision without retraining the entire model.

Common PTQ variants

  • Dynamic PTQ: weights are quantized ahead of time, while activation ranges are calculated dynamically during inference. This avoids a separate static activation-calibration pass but can add runtime overhead.
  • Static PTQ: activation ranges are estimated ahead of time using representative calibration data, then used during deployment.
  • Weight-only PTQ: weights are compressed, while activations and much of the computation may remain FP16/BF16. This is common in LLM inference.

Advantages and limitations

Advantages

  • Can be applied to an existing checkpoint.
  • Usually less expensive than retraining.
  • Useful for deployment and inference optimization.

Limitations

  • Quantization error can reduce task quality.
  • Outliers and poor calibration may harm accuracy.
  • Very low bit-widths may need specialized methods or adaptation.

11 · Training-time adaptation

Quantization-Aware Training (QAT)

Quantization-Aware Training makes the model experience quantization effects during training or fine-tuning. The training graph inserts fake-quantization operations (or quantize/dequantize simulation nodes) so the forward pass reflects rounding and clipping errors that will occur in the deployed low-precision model.

The model can then adjust its trainable parameters to become more robust to those errors. In common implementations, the quantization operations are simulated during training; the final deployment artifact is converted to the target quantized representation.

Why can QAT preserve accuracy better?

PTQ exposes a fixed trained model to lower precision after training has finished. QAT exposes the model to simulated rounding and clipping during optimization. The training process can therefore adjust parameters to reduce the effect of quantization noise on the task's loss.

Many frameworks use a straight-through estimator (STE) or a related gradient approximation because rounding is not differentiable in the ordinary sense. The exact implementation depends on the framework and quantization method.

QAT is not a guarantee of zero accuracy loss. It can improve robustness compared with PTQ, but the result depends on architecture, bit width, training data, calibration choices, quantization granularity, and deployment kernels. It also costs additional training compute.

12 · Large language models

How quantization is used with LLMs

LLMs are Transformer-based neural networks with large weight matrices in attention and feed-forward layers. These matrices dominate parameter storage. Quantizing those weights can substantially reduce the memory needed to load a model for inference.

Common LLM precision choices

  • FP16 / BF16: common reduced-precision floating-point formats for loading, training, or inference on supported accelerators.
  • INT8: an 8-bit representation that can reduce weight memory substantially. Some methods handle activation outliers separately to preserve accuracy.
  • 4-bit: very low-bit weight representations that can make larger models practical on constrained GPUs, often with group-wise scales and specialized formats.

Weight-only quantization and mixed-precision computation

A common LLM inference configuration stores weights in 4-bit or 8-bit form but performs some computations using FP16 or BF16. This is often described as weight-only quantization or a mixed-precision quantized workflow. “The model is 4-bit” does not necessarily mean every tensor and every intermediate operation runs in 4-bit arithmetic.

LLM.int8 and outlier handling

Some transformer activations contain a small number of unusually large values (outliers). A naïve INT8 conversion can cause these values to dominate the scaling range and reduce precision for the majority of values. LLM.int8-style methods use vector-wise quantization and handle outlier dimensions separately in higher precision. This is one example of a quantization method designed around Transformer behavior.

QLoRA is related to quantization, but it is not the same as classical QAT

QLoRA is a memory-efficient fine-tuning approach. It loads a frozen base model in 4-bit form and trains a relatively small set of low-rank adapter parameters. The frozen base weights are not updated in the same way as a full-parameter QAT workflow. Adapter parameters and computation may use a higher precision such as BF16 or FP16.

Connection to a fine-tuning tutorial If a Llama fine-tuning notebook loads the base model with a 4-bit BitsAndBytesConfig and then attaches LoRA adapters, it is typically demonstrating a QLoRA-style workflow—not proof that every fine-tuning workflow uses QAT.

Where quantization fits in the LLM lifecycle

  1. Choose a base model: identify the checkpoint, architecture, license, context length, and serving hardware.
  2. Choose the objective: inference memory reduction, lower latency, edge deployment, or fine-tuning within a GPU budget.
  3. Select a precision and method: FP16/BF16, INT8, 4-bit weight-only, or a supported activation-aware scheme.
  4. Quantize or load a quantized checkpoint: configure the backend and quantization parameters.
  5. Evaluate: compare task quality, latency, throughput, peak VRAM, and generation behavior against the reference model.
  6. Deploy: serve only after validating the same hardware and workload profile expected in production.

13 · Hands-on code

Python examples

The first example implements a simple affine quantizer so the scale and zero-point calculation are visible. It is educational code—not a replacement for optimized production quantization libraries.

Example 1: implement affine quantization with NumPy

Python · Manual quantization and dequantization
import numpy as np


def quantize_affine_uint8(values):
    """Quantize a non-empty array into uint8 using min-max affine mapping."""
    x = np.asarray(values, dtype=np.float32)
    if x.size == 0:
        raise ValueError("values must contain at least one element")

    x_min = float(np.min(x))
    x_max = float(np.max(x))
    q_min, q_max = 0, 255

    # Avoid division by zero for a constant-valued tensor.
    if np.isclose(x_max, x_min):
        scale = 1.0
        zero_point = int(np.clip(np.rint(q_min - x_min), q_min, q_max))
    else:
        scale = (x_max - x_min) / (q_max - q_min)
        zero_point = int(np.clip(
            np.rint(q_min - x_min / scale), q_min, q_max
        ))

    # np.rint uses round-half-to-even (banker's rounding).
    q = np.clip(np.rint(x / scale + zero_point), q_min, q_max)
    return q.astype(np.uint8), scale, zero_point


def dequantize_uint8(q, scale, zero_point):
    """Reconstruct approximate float32 values from uint8 values."""
    q = np.asarray(q, dtype=np.uint8)
    return scale * (q.astype(np.float32) - zero_point)


values = np.array([-20.0, 0.0, 250.0, 1000.0], dtype=np.float32)
quantized, scale, zero_point = quantize_affine_uint8(values)
reconstructed = dequantize_uint8(quantized, scale, zero_point)

print("Original:      ", values)
print("Quantized:     ", quantized)
print("Scale:         ", scale)
print("Zero-point:    ", zero_point)
print("Reconstructed:", reconstructed)

Illustrative output (rounding can vary by implementation)

Original:       [ -20.    0.  250. 1000.]
Quantized:      [  0   5  68 255]
Scale:          4.0
Zero-point:     5
Reconstructed: [ -20.    0.  252. 1000.]

The original value 250 is reconstructed as approximately 252 in this implementation because the quantized value is an integer step. The error is expected; quantization is a lossy approximation.

Production note Real quantization libraries support signed and unsigned types, per-channel/group scales, specialized rounding, clipping policies, packing, backend-specific operators, and numerical edge cases. The function above is deliberately small so the math is easy to inspect.

Example 2: load a Transformers model in 4-bit with bitsandbytes

This example shows the common shape of a 4-bit LLM loading configuration. Replace the model ID with a checkpoint you are permitted to access. The exact package versions, GPU support, and configuration options should be checked against the versions installed in your environment.

Python · Hugging Face Transformers + bitsandbytes
import torch
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
)

MODEL_ID = "your-org/your-instruct-model"

quant_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=quant_config,
    device_map="auto",
)

prompt = "Explain model quantization in simple terms."
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)

with torch.inference_mode():
    output_ids = model.generate(
        **inputs,
        max_new_tokens=120,
        do_sample=False,
    )

print(tokenizer.decode(output_ids[0], skip_special_tokens=True))

Use torch.float16 for the compute dtype if BF16 is not supported by the selected hardware. This does not imply that every model operation or activation is stored in 4-bit form.

14 · Engineering decisions

Accuracy, speed and memory trade-offs

Quantization is a compression technique, so some numerical information is generally lost when a continuous range is mapped to a finite set of integer levels. The engineering goal is not merely to make the model smaller; it is to find a precision and method that meet the application's quality and performance requirements.

Sources of quality degradation

  • Rounding: nearby real numbers may map to the same integer.
  • Clipping: values outside the chosen calibration range map to an endpoint.
  • Outliers: extreme values can stretch the range and reduce resolution for the majority of values.
  • Coarse granularity: one scale for an entire tensor may not represent every channel or group equally well.
  • Very low bit width: fewer levels make reconstruction more difficult, especially for sensitive layers.

What should be measured?

MetricWhat it tells youExample measurement
Task qualityWhether the model still performs its intended task.Accuracy, exact match, perplexity, benchmark score, or human evaluation.
Peak VRAMWhether the model fits on target hardware under realistic load.Maximum allocated GPU memory at target context and batch size.
Time to first tokenHow long a user waits before generation begins.TTFT in milliseconds.

End-to-end latencyThe user-observed response time.Prompt processing + generation + serving overhead.

Recommended evaluation method

  1. Keep an unquantized FP16/BF16 or FP32 checkpoint as a reference.
  2. Use the same evaluation prompts, decoding parameters, and hardware for each candidate.
  3. Measure quality, peak memory, TTFT, decode speed, and end-to-end latency.
  4. Test multiple context lengths and batch sizes; KV cache can change the memory picture.
  5. Choose the smallest or fastest model that still meets the quality threshold.

15 · Learning and implementation roadmap

Plan of action

Use this sequence to move from the mathematics in the lecture to a real quantized LLM deployment.

  1. Master the data types. Be able to explain the difference between FP32, FP16, BF16, INT8 and INT4, including bits per value and approximate memory.
  2. Work through the quantization equations. Calculate scale and zero-point for one non-negative range and one range containing negative values. Verify by quantizing and dequantizing sample values.
  3. Understand calibration. Learn why representative data is needed for activation ranges and compare min–max, percentile, histogram, and moving-average strategies.
  4. Compare PTQ and QAT. Draw each workflow from memory. Explain why QAT simulates rounding/clipping during training and why PTQ is usually cheaper to apply.
  5. Run a quantized inference experiment. Load one accessible model in FP16/BF16, then in 8-bit or 4-bit. Record memory, latency, and output quality.
  6. Connect quantization to fine-tuning. Identify whether a notebook uses PTQ, QAT, or QLoRA. Do not treat those terms as interchangeable.
  7. Write an evaluation report. Compare the reference and quantized model on a fixed test set and explain the quality/performance trade-off.
Suggested hands-on deliverable Create a small notebook with (1) the NumPy quantizer, (2) a 4-bit or 8-bit model-loading example, and (3) a comparison table containing model size, peak VRAM, latency, tokens/second, and task-quality results.

16 · Interview preparation

Interview questions and answers

1. What is model quantization?

Model quantization reduces the number of bits used to represent weights and/or activations, for example by converting FP32 values to INT8 or a 4-bit format. This reduces memory use and can improve inference efficiency when supported by the hardware.

2. Why do we quantize an LLM?

To reduce model-weight memory, lower memory bandwidth requirements, and make deployment on smaller GPUs or edge devices more practical. Speed improvements depend on the hardware and kernels.

3. What is the scale factor?

Scale determines how much real-valued distance corresponds to one integer step. In affine quantization, it is commonly calculated as the real range divided by the integer range.

4. What is a zero-point?

The zero-point is the integer value used to represent real zero. It allows an asymmetric real-valued interval to map correctly into an integer interval.

5. What is the difference between symmetric and asymmetric quantization?

Symmetric quantization uses a real range centered at zero and commonly a zero-point of zero. Asymmetric quantization maps the observed minimum and maximum independently and may require a non-zero zero-point.

6. What is calibration?

Calibration estimates the value ranges and quantization parameters, often by passing representative data through the model and collecting activation statistics.

7. What is PTQ?

Post-Training Quantization converts a model after its original training is complete. Static PTQ often uses representative calibration data to estimate activation ranges.

8. What is QAT?

Quantization-Aware Training simulates quantization effects during training or fine-tuning so the model can adapt to rounding and clipping errors before deployment.

9. Is QLoRA the same as QAT?

No. QLoRA usually freezes a 4-bit quantized base model and trains low-rank adapter parameters. QAT explicitly simulates quantization effects in the training graph. They solve related memory/accuracy problems but are different methods.

10. Does INT8 always make inference faster?

No. It reduces storage and may reduce memory traffic, but speed depends on hardware support, optimized kernels, batch size, sequence length, and workload characteristics.

11. Why can quantization reduce accuracy?

Because rounding maps continuous values to discrete levels, and clipping can discard out-of-range values. Poor calibration, outliers, coarse quantization granularity, or very low bit widths can increase the error.

12. What is the difference between FP16 and INT8?

FP16 is a 16-bit floating-point format. INT8 is an 8-bit integer format and usually needs a scale and zero-point to represent the model's real-valued tensors. FP16 halves raw storage compared with FP32; INT8 uses one quarter of FP32's raw per-value storage.

One-minute interview answerQuantization compresses neural-network weights and sometimes activations by representing them with fewer bits. A scale and zero-point map real values to a limited integer range, and calibration estimates the ranges for that mapping. PTQ applies quantization after training, while QAT simulates quantization during training so the model can adapt. In LLMs, 8-bit and 4-bit weight quantization can reduce VRAM substantially, but the final choice must be evaluated for quality, latency, and real deployment memory. QLoRA is a related low-memory fine-tuning technique, not the same as classical QAT.
