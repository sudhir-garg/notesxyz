01 · Lesson overview

What are we building?

The lesson demonstrates how to adapt the Llama 2 7B Chat model to a custom instruction dataset without updating every parameter in the base model.

The demonstrated approach combines three ideas:

PEFT

Parameter-Efficient Fine-Tuning reduces the number of trainable parameters. Most pretrained model weights remain frozen.

LoRA

Small trainable low-rank adapter matrices learn task-specific updates in selected model layers.

4-bit loading

BitsAndBytes loads the frozen base weights in a compact 4-bit representation to reduce GPU memory use.

TerminologyThe transcript sometimes says “PFT” or “parameter efficient transfer learning.” The standard library and research term is **PEFT — Parameter-Efficient Fine-Tuning**. The example is a QLoRA-style workflow: a quantized base model plus trainable LoRA adapters.

02 · Architecture

End-to-end fine-tuning workflow

The pipeline has four major inputs: a pretrained checkpoint, a tokenizer, a formatted training dataset, and a training configuration. The quantized model is wrapped with LoRA adapters; SFT then updates the adapter parameters.

  1. Install the required Python libraries and authenticate to the model hub.
  2. Load and inspect a human–assistant instruction dataset.
  3. Convert every example into the prompt format expected by Llama 2 Chat.
  4. Configure and load the base model using 4-bit NF4 quantization.
  5. Attach LoRA adapters using PEFT.
  6. Run supervised fine-tuning (SFT), inspect the loss, and save the adapter.
  7. Reload the base model and adapter together, then test unseen prompts.
03 · Core concepts

PEFT, LoRA and QLoRA: how they fit together

Full fine-tuning vs. parameter-efficient fine-tuning

In full fine-tuning, gradients update the model’s original trainable weights. For a multi-billion-parameter model this creates substantial memory requirements: model weights, gradients, optimizer states, and activations all consume memory.

In PEFT, most base-model parameters are frozen and a comparatively small set of additional parameters is trained. LoRA is one PEFT method: it represents the task-specific weight update with low-rank matrices.

Full fine-tuning

Update the original model parameters. Flexible, but generally much more expensive in memory and compute.

Many trainable parametersLarge optimizer state

LoRA / PEFT

Freeze the base weights and train compact adapter parameters in selected layers.

Fewer trainable parametersSmall adapter checkpoint

What makes this QLoRA?

QLoRA combines a quantized base model with LoRA adapters. In this lesson, the base model is loaded in 4-bit NF4, while adapter parameters are trained using a higher-precision compute path such as FP16 or BF16.

Do not conflate the techniquesQuantization compresses numerical representations. LoRA adds low-rank trainable updates. PEFT is the broader family of parameter-efficient methods. QLoRA combines 4-bit base-model quantization with LoRA training.
04 · Hardware

Why is GPU memory a constraint?

A 7-billion-parameter model requires substantial storage even before training begins. A rough lower-bound estimate is parameter count multiplied by bytes per stored parameter.

Weight representationBytes per parameter (approx.)7B weights only (approx.)Notes
FP32428 GBHigh precision; large storage footprint
FP16 / BF16214 GBCommon reduced-precision model storage
INT817 GBQuantized representation; metadata/overhead excluded
4-bit0.53.5 GBTheoretical raw weight estimate; practical footprint is larger

These are decimal, weight-only estimates. Actual GPU usage also depends on quantization metadata, non-quantized modules, temporary buffers, activations, sequence length, batch size, CUDA context, and framework implementation.

What else consumes memory during training?

Model parameters

The loaded base model and the trainable adapter weights.

Gradients

Gradient tensors for parameters being trained.

Optimizer states

Extra state used by Adam-family optimizers to update trainable parameters.

Activations and workspace

Intermediate tensors retained or recomputed during forward/backward passes.

Why QLoRA helpsThe base model’s quantized weights require less memory, and LoRA keeps the trainable parameter set relatively small. This can make fine-tuning feasible on a smaller GPU than full fine-tuning, but it does not guarantee that every 7B training configuration will fit in a 15 GB device.

08 · Prompt formatting

Convert examples to the Llama 2 Chat format

Llama 2 Chat expects structured instruction boundaries. The transcript shows the following pattern:

Llama 2 Chat serialization pattern
<s>[INST] <<SYS>>
You are a helpful, accurate assistant.
<</SYS>>

User instruction goes here.
[/INST] Assistant response goes here.</s>
Token / markerRole in the example
<s>Beginning-of-sequence marker
[INST]Starts the user instruction block
<<SYS>> ... <</SYS>>Wraps the system instruction
[/INST]Marks the end of the user instruction and start of the assistant answer
</s>End-of-sequence marker for the serialized example

Formatting function

Notebook cell · convert instruction / answer rows
SYSTEM_PROMPT = "You are a helpful, accurate assistant."

def format_llama2(example):
    instruction = (example.get("instruction") or example.get("human") or "").strip()
    extra_input = (example.get("input") or "").strip()
    answer = (example.get("output") or example.get("assistant") or "").strip()

    if extra_input:
        instruction = f"{instruction}\n\nAdditional context:\n{extra_input}"

    text = (
        "<s>[INST] <<SYS>>\n"
        f"{SYSTEM_PROMPT}\n"
        "<</SYS>>\n\n"
        f"{instruction} [/INST] {answer}</s>"
    )
    return {"text": text}

train_dataset = train_raw.map(format_llama2)
eval_dataset = eval_raw.map(format_llama2)

print(train_dataset[0]["text"])
Important: this code assumes field namesIt handles the example schemas instruction/input/output and human/assistant. If the selected dataset has a single text column or a different conversation structure, write a formatter for that schema instead of applying this function unchanged.
Which tokens contribute to the loss?With this plain-text text dataset, standard causal-language-model SFT generally computes loss over the serialized sequence, including prompt tokens as well as answer tokens (subject to padding and trainer behavior). If the goal is to train only on assistant completions, use a prompt–completion or conversational dataset format and configure completion-only / assistant-only loss with a chat template that supports it. Do not assume the trainer masks the prompt automatically for a plain text column.

Keep the same serialization convention during training and inference. If a model tokenizer provides an official chat template, prefer the tokenizer’s template rather than manually constructing a different format. Chat templates are model-specific.

09 · Quantization

Configure 4-bit NF4 quantization

The lesson loads the base model in 4-bit mode using BitsAndBytes. The example selects NF4 as the 4-bit quantization type and uses FP16 for computation. It also discusses nested (double) quantization as an optional memory optimization.

Notebook cell · BitsAndBytesConfig
import torch
from transformers import BitsAndBytesConfig

# Use BF16 only when the GPU supports it; otherwise use FP16.
if torch.cuda.is_available() and torch.cuda.is_bf16_supported():
    compute_dtype = torch.bfloat16
else:
    compute_dtype = torch.float16

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=compute_dtype,
    bnb_4bit_use_double_quant=True,
)
ParameterMeaningExample setting
load_in_4bitLoad supported base-model linear weights in 4-bit form.True
bnb_4bit_quant_type4-bit quantization format."nf4"
bnb_4bit_compute_dtypeDatatype used for compute operations with quantized weights.FP16 or BF16
bnb_4bit_use_double_quantApplies a second quantization to quantization constants to save additional memory.True in this updated example
Storage precision is not compute precision4-bit describes how the frozen base weights are represented in memory. The computation is performed using the configured higher-precision compute datatype. Do not describe this as converting every tensor and every operation into ordinary INT4 arithmetic.
10 · Load model and tokenizer

Load the quantized Llama 2 checkpoint

Transformers provides AutoModelForCausalLM for causal language models and AutoTokenizer for converting text to token IDs.

Notebook cell · model and tokenizer
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL_ID = "meta-llama/Llama-2-7b-chat-hf"

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=bnb_config,
    device_map="auto",
    dtype=compute_dtype,
)

model.config.use_cache = False  # commonly disabled during gradient-checkpointed training

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, use_fast=True)

# Llama 2 tokenizers may not define a distinct padding token.
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

tokenizer.padding_side = "right"

Why set the padding token? Batches often contain sequences of different lengths. Padding makes their tensor dimensions consistent. Reusing the EOS token as padding is a common causal-LM setup when a dedicated pad token is absent; the data collator and label masking must still handle padding correctly.

Why disable use_cache during training? The generation key/value cache is useful for autoregressive inference, but typically unnecessary during training and can conflict with gradient checkpointing. Re-enable caching for inference if appropriate.

11 · Adapter configuration

Attach LoRA adapters with PEFT

LoRA is applied to selected linear projections inside the Transformer. Instead of updating the original matrix directly, the method learns a low-rank update. The rank, scaling coefficient, dropout, and target modules control the adapter configuration.

Notebook cell · LoRA configuration
from peft import LoraConfig, prepare_model_for_kbit_training

# Prepare the quantized checkpoint for adapter training.
model = prepare_model_for_kbit_training(model)

lora_config = LoraConfig(
    r=64,                         # rank used in the video
    lora_alpha=16,                # scaling coefficient used in the video
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    bias="none",
    task_type="CAUSAL_LM",
)
LoRA parameterWhat it controlsPractical note
rRank of the low-rank update matrices.Higher rank increases adapter capacity and trainable parameter count.
lora_alphaScaling applied to the adapter update.Interpret together with rank; the conventional LoRA scaling is alpha divided by rank.
target_modulesModel layers that receive LoRA modules.Names must match the architecture. The example targets Llama attention projections.
lora_dropoutDropout applied on the adapter path during training.May help regularize small datasets.
biasWhether selected bias parameters are trained.none is a common adapter setup.
task_typeDeclares the model task to PEFT.CAUSAL_LM for autoregressive language modeling.
Target modules are architecture-dependentThe transcript mentions target modules but does not spell out the exact list. The list above is a common Llama attention-projection example, not a verified copy of the video’s notebook. Always inspect the model’s module names and choose targets deliberately.

For a quick parameter-count check after wrapping the model in PEFT, use model.print_trainable_parameters(). With a Trainer-based workflow, PEFT is typically attached through the trainer’s peft_config argument.

12 · Supervised fine-tuning

Configure the trainer and start training

The lesson uses TRL’s SFTTrainer and supervised fine-tuning. Training arguments control batch size, gradient accumulation, learning rate, optimizer, scheduler, sequence length, logging, checkpoints, and precision.

Example training configuration

Notebook cell · SFTConfig and SFTTrainer
from trl import SFTConfig, SFTTrainer

OUTPUT_DIR = "./llama2-7b-chat-custom-adapter"

training_args = SFTConfig(
    output_dir=OUTPUT_DIR,
    num_train_epochs=1,
    max_steps=250,                  # matches the step count reported in the demo
    per_device_train_batch_size=1,
    per_device_eval_batch_size=1,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    weight_decay=0.001,
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,
    optim="paged_adamw_8bit",
    logging_steps=25,
    save_steps=50,
    save_total_limit=2,
    max_length=1024,
    dataset_text_field="text",
    packing=False,
    gradient_checkpointing=True,
    fp16=(compute_dtype == torch.float16),
    bf16=(compute_dtype == torch.bfloat16),
    report_to="none",
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    processing_class=tokenizer,
    peft_config=lora_config,
)

trainer.train()
max_steps overrides epochsIn the Transformers Trainer training loop, a positive max_steps determines the total number of update steps and takes precedence over the epoch-derived step count. The example includes both to make the intent visible, but the actual run is bounded by 250 steps.

Key training parameters

ParameterExplanation
Per-device batch sizeNumber of examples processed per device in one micro-batch.
Gradient accumulationAccumulates gradients across multiple micro-batches before an optimizer update. Approximate effective batch size = micro-batch × accumulation × number of devices.
Learning rateControls the size of adapter parameter updates.
Cosine schedulerAdjusts learning rate over the run following a cosine-shaped schedule.
Paged AdamW 8-bitMemory-conscious optimizer variant supported by BitsAndBytes setups.
Max sequence lengthCaps the tokenized sample length. Long samples may be truncated.
Gradient checkpointingReduces activation memory by recomputing selected activations during backward propagation, at added compute cost.
Logging / save stepsControls how often metrics are logged and checkpoints are written.

Understand the effective batch size

Effective batch size ≈ 1 × 4 × 1 GPU = 4 examples per optimizer update

This is an approximation; the final partial batch and distributed training can change the exact count.

Sequence length is a memory leverReducing max_length is often an effective way to lower activation memory. Choose a length that still preserves the complete instruction and answer for the target task.

What should be monitored?

  • Training loss: whether the model is learning the training examples.
  • Validation loss: whether performance on held-out examples improves or degrades.
  • GPU memory: whether the run is near the device limit.
  • Throughput: examples or tokens processed per second.
  • Generated samples: whether answers follow the expected format and remain useful.

15 · Test generation

Run inference with the fine-tuned model

The video uses a text-generation pipeline to test a general question and then a question drawn from the training examples. A direct generation example makes the prompt and generated tokens explicit:

Notebook cell · generate a response
prompt = (
    "<s>[INST] <<SYS>>\n"
    "You are a helpful, accurate assistant.\n"
    "<</SYS>>\n\n"
    "What is a large language model? [/INST]"
)

inputs = tokenizer(prompt, return_tensors="pt").to(inference_model.device)

with torch.no_grad():
    output_ids = inference_model.generate(
        **inputs,
        max_new_tokens=180,
        do_sample=True,
        temperature=0.7,
        top_p=0.9,
        pad_token_id=tokenizer.eos_token_id,
        eos_token_id=tokenizer.eos_token_id,
    )

new_tokens = output_ids[0, inputs["input_ids"].shape[1]:]
print(tokenizer.decode(new_tokens, skip_special_tokens=True))

How should the model be evaluated?

Do not judge fine-tuning from one example. Build a small, fixed evaluation set that includes prompts not used in training. Evaluate answer relevance, factuality, completeness, formatting, refusal behavior where relevant, and regressions on general capabilities.

Compare against the base modelRun the same prompts through the original Llama 2 Chat checkpoint and the fine-tuned adapter model. The comparison helps determine whether the fine-tuning actually improved the target task or merely changed the response style.
16 · Practical checklist

Troubleshooting and best practices

SymptomLikely causeWhat to check
Access denied while loading modelGated repository access or missing authenticationAccept the model license, request access where required, and authenticate the runtime.
CUDA out-of-memorySequence length, micro-batch, activations, or model placement too largeLower batch size and sequence length; use gradient accumulation/checkpointing; verify 4-bit loading and device map.

Before launching a full run

  • Print the dataset columns and inspect at least five formatted examples.
  • Tokenize a few examples and verify that the answer is not truncated.
  • Check GPU type, total memory, CUDA availability, and BF16 support.
  • Run a short smoke test with a small subset and a few optimizer steps.
  • Record the base model ID, dataset version, random seed, package versions, and configuration.
  • Keep a validation set and compare generations against the original model.
  • Save adapter checkpoints and training logs outside the temporary runtime.
Safety and data governanceOnly train on data you are authorized to use. Remove personal or confidential information where it is not needed, review the base model license and acceptable-use requirements, and evaluate the fine-tuned model for harmful or unreliable behavior before deployment.

Frequently asked questions

1. What is PEFT?

A family of fine-tuning methods that reduces the number of parameters that must be trained or stored. LoRA is one method in this family.

2. What is LoRA?

Low-Rank Adaptation learns a compact low-rank update to selected weight matrices while the original pretrained weights are typically frozen.

3. What is QLoRA?

A technique that quantizes the pretrained base model, commonly to 4-bit NF4, and trains LoRA adapters on top of it.

4. Why use NF4?

NF4 is a 4-bit datatype designed for normally distributed weights and is commonly recommended for training 4-bit base models in QLoRA workflows.

5. Why does the tokenizer matter?

The tokenizer maps text to token IDs. Chat formatting and special-token boundaries must match the format expected by the model.

6. What does SFT mean?

Supervised Fine-Tuning trains the model on examples of desired inputs and outputs, using a supervised next-token prediction objective.

7. Why save an adapter rather than the full model?

Only the trainable adapter weights need to be saved for a PEFT run; the original base checkpoint can be reused when loading the adapter.

8. Does a training loss of 1.36 prove the model is good?

No. Training loss is only one signal. Held-out validation and task-specific generation evaluation are necessary.

Quick revision checklist

  • PEFT reduces trainable parameters.
  • LoRA learns low-rank updates in selected layers.
  • QLoRA combines quantized base weights and LoRA adapters.
  • NF4 is the 4-bit quantization type used in the walkthrough.
  • Dataset records must match the correct Llama 2 chat format.
  • SFTTrainer performs supervised fine-tuning.
  • Save and reload the adapter with its matching base model.
  • Validate on prompts that were not used during training.
